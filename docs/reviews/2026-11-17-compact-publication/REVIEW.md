# 无损发布封装复核

## 问题与改动

完整静态发布包约145MB，连续四次在300秒的上传环节超时，尚未保存新版本。829份独立下载HTML重复包含相同的脚本、样式和页面片段。普通gzip加大压缩级别只能节省0.05%。

增加 `hosting/build.cjs` 与 `hosting/worker.mjs`：将完整静态构建拆成按SHA-256去重的字节块，在服务器中按原顺序解压并流式返回。原1501个文件、所有网址、HTML下载和内容保持不变。通常构建和离线归档仍使用 `node build.cjs` 的完整静态结果。新封装只用于部署；不添加浏览器端运行依赖，不改经济模型或教学文字。

- 1501文件，原始总字节数265,765,914；构建时全部还原验证，差异0。
- 2460个唯一块；Worker源码11,621,896字节，gzip约8.5MB。

- 测试包括扩展名省略、参数保留、HEAD、ETag/304、不存在路径、错误编码和方法限制。
- 封装后的本地Chrome检查48个状态（1440/390/320），涵盖首页、目录、速通、三户分货、代表章节、习题直达、键盘、触摸与减少动态效果；9份HTTP响应与静态构建完全一致。
- 压缩块缓存限4MiB；仅按请求流式解压，不在启动时把整站展开到内存。
- 完整静态参考取自此前核验的发布构建，未从带有额外陈旧文件的本地dist目录打包。
- 本轮未修改 `src/`、主 `build.cjs`、审校哈希、教材模型或题目答案。审核哈希无需因新增部署封装刷新。

## 发布与验收约定

使用相同Sites项目、公开权限和原网站地址；只把部署清单从静态资产切换到标准Worker入口。保留旧版本，可回滚。上线前检查原页面在1440、390、320宽度的显示与操作；上线后对公开网址再检查，并核对返回文件。实际结果和截图保存在本次交付与外盘归档，不能用本文件推断已发布。

运行能力按平台的[Web标准接口](https://developers.cloudflare.com/workers/runtime-apis/web-standards/)和[资源限制](https://developers.cloudflare.com/workers/platform/limits/)复核；本机Node的载入耗时不是云端性能承诺。真实手机与Safari仍需另行验证。
